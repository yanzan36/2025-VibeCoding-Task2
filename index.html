Phase 1 · HTML/CSS 環境與占位骨架
個人前端工程師網站 · Hero 區占位

這裡是 主視覺 Hero 區，未來會放上前端工程師的個人介紹與行動呼籲。

目前這一區是簡化版的占位內容，實際上線時會改成一句話自我介紹、核心職稱（例如 Frontend Developer）以及明確的行動按鈕（例如瀏覽作品集、下載履歷等）。

在 Phase 1 階段，只先建立版面與結構，方便之後用 Section SDD 的 Prompt 產生完整的 Hero 區文案與版面，再把新的 section 程式碼貼回來使用。

建議未來這裡放上清楚的一句話定位、主要服務內容與一組明顯的 CTA，讓訪客一進站就理解你是什麼樣的工程師、適合什麼樣的合作案。

給開發者的提醒：之後會用 Section SDD 的 Prompt 產生新的 Hero section，請把新的 section 程式碼整段貼在「SECTION:HERO-START / SECTION:HERO-END」註解中間， 完全取代現在這一區的所有內容。

SECTION · ABOUT

關於我（About 區占位內容）

這裡將會簡潔介紹你的背景、工作經驗與前端技術定位，讓訪客快速了解你是怎樣的一位工程師。

目前這一區是 About 區的占位內容，先提供一個乾淨、可閱讀的結構。未來正式內容可以包含自我介紹、職涯重點、技術信念與目前專注的領域等等。

你可以在 Section SDD 中，針對「關於我」這一頁面定義更完整的敘事與小標題，產出新的 section 程式碼，取代這裡目前看到的示意文字與排版。

給開發者的替換指引： 之後會用 Section SDD 的 Prompt 產生新的 About section， 請把新的 section 程式碼整段貼在「SECTION:ABOUT-START / SECTION:ABOUT-END」兩個註解中間， 完全覆蓋現在這一區的內容，不用再額外修改其他地方。

建議正式版 About 區可包含：

  • 職涯簡介與專長領域
  • 目前任職或主要身分
  • 使用最順手的技術堆疊
  • 個人價值觀與開發風格

這個欄位目前僅作為排版占位，幫助你先確認 RWD 效果與閱讀節奏。正式內容與結構，都會在之後的 Section SDD 階段重新設計。

可以把這個區塊視為「未來會被完整替換的插槽」，只要記得新的程式碼要放在相同註解之間即可。

SECTION · SKILLS

技能（Skills 區占位內容）

這裡將列出你擅長的前端技能、工具與相關能力，未來可以細分成前端核心、周邊工具與軟性技能等分組。

目前這一區是 技能區的占位內容，主要目的在提供一個可被覆蓋的版型，讓之後產生的 Skills section 可以直接貼上取代，不需要重新思考排版。

實際使用 Section SDD 時，可以針對技能分類、熟悉程度與使用情境（例如專案經驗）做更細緻的規劃，將敘事與標籤設計得更貼近你的個人品牌。

給開發者的替換指引： 之後會用 Section SDD 的 Prompt 產生新的 Skills section， 請把新的 section 程式碼整段貼在「SECTION:SKILLS-START / SECTION:SKILLS-END」兩個註解中間， 完整取代現在這一區。若有新增 class 名稱，可在 CSS:HERO / CSS:SKILLS 等區塊中擴充樣式。

下方列出的技能僅作為視覺占位，可在正式版中自由修改或重新分組：

  • HTML5 / 語意化標籤
  • CSS3 / RWD 響應式設計
  • Flexbox & Grid 版面
  • 設計系統思維
  • 版本控制（Git）
  • UI / UX 溝通與協作
  • 跨裝置相容性調整

這些標籤目前只是「視覺上的 placeholder」，讓你在 Phase 1 就能大致感受到 Skills 區的密度與節奏。未來若用 Section SDD 重新產出整個 section，請照指引整段貼上即可。

SECTION · PROJECTS

作品集（Projects 區占位內容）

這裡將展示你曾經參與或個人開發的專案，包含簡短描述、技術堆疊與連結，讓訪客從實際作品理解你的能力。

目前這一區是 Projects 區的占位內容，示範「作品卡片列表」的基本結構與層次。正式內容可以換成真實專案、線上 Demo 或 GitHub 連結。

示意作品 · 個人作品集首頁

這裡未來會顯示作品名稱、開發時間與簡短的一句話說明，幫助訪客快速掃描你的專案重點。

目前文字僅作為占位，未來可替換為實際專案說明，例如：改版重點、解決的問題、負責的角色與主要技術等。

SECTION · CONTACT

聯絡我（Contact 區占位內容）

這裡會提供訪客與你聯繫的方式，例如 Email、社群或 GitHub 等，並簡單說明適合合作的主題與專案類型。

目前這一區是 聯絡方式的占位內容，主要示範常見的聯絡管道與資訊排版。接下來你可以在 Section SDD 中，針對聯絡區重新設計文案與欄位結構。

  • Email（示意用，占位文字）：
    建議使用專屬工作信箱 hello@example.com
  • 手機（示意用，占位文字）：
    +886 900 000 000
  • GitHub（示意用，占位文字）：
    https://github.com/yourname
  • LinkedIn（示意用，占位文字）：
    https://www.linkedin.com/in/yourname

在實際上線的版本中，可以利用這一側的空間，說明你偏好接觸的合作方式（例如：遠端接案、長期顧問、短期開發支援），以及回覆訊息的大致時間。

建議在 Section SDD 階段規劃一段簡短的「合作說明」，例如： 目前開放的專案類型、擅長處理的問題與不接的專案範圍，讓雙方在聯絡前就有更清楚的期待。

給開發者的替換指引： 之後會用 Section SDD 的 Prompt 產生新的 Contact section， 請把新的 section 程式碼整段貼在「SECTION:CONTACT-START / SECTION:CONTACT-END」兩個註解中間， 完全取代現在這一區。若有新增表單或欄位，只要維持在同一個 section 結構中即可。
